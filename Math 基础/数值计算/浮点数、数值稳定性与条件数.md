# 浮点数、数值稳定性与条件数

先抓住一句话：

> 数学里的实数像一条连续数轴；计算机里的浮点数更像覆盖这条数轴的一组有限刻度，而且越远离 0，刻度通常越稀。数值计算研究的不是公式“理论上对不对”，而是有限刻度上算出来还靠不靠谱。

很多训练中的 `NaN`、梯度爆炸、softmax 溢出和线性求解异常，不是模型突然不懂数学，而是公式的写法忽略了浮点表示和误差传播。

## 1. 浮点数是有限的科学计数法

一个二进制浮点数可以粗略写成

$$
(-1)^s\times m\times2^e,
$$

其中 $s$ 是符号，$m$ 是有效数字（significand），$e$ 是指数。IEEE 754 还规定了正负零、无穷、NaN 和次正规数等特殊情况。

指数位决定大致能表示多大、多小的数量级；有效数字位决定同一数量级内能分得多细。因此：

- 浮点数不是均匀分布；
- 大数附近相邻可表示数的绝对间隔更大；
- 很多十进制小数（如 0.1）不能被有限二进制精确表示；
- 一次基本运算通常要舍入到最近的可表示数。

这解释了为什么 `0.1 + 0.2 == 0.3` 可能为假。正确问题通常不是“是否逐位相等”，而是“误差是否在任务允许的绝对/相对容差内”。

## 2. 机器精度、ULP 与范围是不同概念

机器 epsilon 常定义为使 $1+\varepsilon>1$ 的最小浮点间隔附近量。NumPy 可查看：

```python
import numpy as np

for dtype in (np.float16, np.float32, np.float64):
    info = np.finfo(dtype)
    print(dtype.__name__, "eps=", info.eps,
          "tiny=", info.tiny, "max=", info.max)
```

- `eps` 描述 1 附近的相对分辨率；
- `tiny` 是最小的正规正数，不等于包括次正规数后的绝对最小正数；
- `max` 描述最大有限值；
- ULP（unit in the last place）描述某个具体数附近相邻浮点数的间隔。

精度和动态范围不要混为一谈。BF16 与 FP32 有相同数量的指数位，因此动态范围相近，但 BF16 有效数字更少；FP16 有更多尾数位，却只有 5 个指数位，更容易溢出或下溢。详见 [BF16和FP16](https://github.com/HaningZS/HaningZS_Notes/blob/8ced9038b7611bcb8c2b2774fb870149df8ef780/LLM%20%E4%B8%8E%E6%99%BA%E8%83%BD%E4%BD%93/%E5%B7%A5%E7%A8%8B/BF16%E5%92%8CFP16.md)。

## 3. 三类常见灾难

### 3.1 溢出与下溢

当绝对值超过可表示上限，会得到 `inf`；非常小的非零值可能进入次正规区或舍入为 0。

例如直接计算 $e^{1000}$ 会溢出。但很多公式只需要相对比例，可以先减去最大值，不改变 softmax：

$$
\frac{e^{z_i}}{\sum_j e^{z_j}}
=
\frac{e^{z_i-m}}{\sum_j e^{z_j-m}},
\qquad m=\max_jz_j.
$$

### 3.2 灾难性消减

两个非常接近的大数相减时，前面的有效数字被抵消，只剩原先舍入误差占比很大的尾部。

例如当 $x$ 很小时，直接计算

$$
\sqrt{1+x}-1
$$

会丢失精度。乘以共轭式可改写为

$$
\frac{x}{\sqrt{1+x}+1},

$$

数学上完全等价，数值上却更稳定。

### 3.3 误差累积与相加顺序

浮点加法不满足严格结合律：

$$
(a+b)+c\ne a+(b+c)
$$

在有限精度下可能成立。大量不同量级的数求和时，从小到大相加、pairwise summation 或 Kahan summation 往往比天真顺序更准。并行 GPU kernel 改变归约顺序后出现末位差异，不必然意味着实现错误，但可能影响严格复现。

## 4. 稳定算法：输出误差像来自一个很小的输入扰动

一个算法若能被解释为“精确解决了一个与原问题非常接近的问题”，通常称为后向稳定。这里要区分：

- **问题条件好不好**：输入发生微小变化，真实答案会不会剧烈变化；
- **算法稳不稳定**：算法是否额外放大舍入误差。

坏条件是问题本身敏感；坏稳定性是解法选得差。稳定算法也救不了极端病态问题，但不稳定算法能把原本良态的问题算坏。

典型稳定改写：

- `log(1 + x)` 在小 $x$ 时用 `log1p(x)`；
- `exp(x) - 1` 在小 $x$ 时用 `expm1(x)`；
- `log(sum(exp(z)))` 用 log-sum-exp 技巧；
- softmax 先减最大 logit；
- 线性方程用 `solve`，最小二乘用 `lstsq`，不要先显式求逆。

## 5. 条件数：问题本身有多敏感

对一般函数 $y=f(x)$，相对条件数粗略衡量

$$
\frac{\text{输出相对变化}}{\text{输入相对变化}}.
$$

对可逆线性系统 $Ax=b$，2-范数条件数为

$$
\kappa_2(A)=\|A\|_2\|A^{-1}\|_2
=\frac{\sigma_{\max}(A)}{\sigma_{\min}(A)}.
$$

当只扰动 $b$ 时，在适当条件下有近似界：

$$
\frac{\|\Delta x\|}{\|x\|}
\lesssim
\kappa(A)
\frac{\|\Delta b\|}{\|b\|}.
$$

所以条件数 $10^6$ 意味着输入中约 $10^{-k}$ 量级的相对误差，最坏情况下可能在输出中放大约百万倍。它是最坏方向的敏感度界，不是每个样本必然都恰好放大这么多。

条件数依赖所选范数，也依赖参数化和单位。把一个特征从“米”换成“毫米”会改变矩阵尺度，常需标准化或预条件。

## 6. 线性系统：为什么不要显式求逆

要求解 $Ax=b$，数学上可写 $x=A^{-1}b$，但代码中通常应写：

```text
x = np.linalg.solve(A, b)
```

而不是：

```text
x = np.linalg.inv(A) @ b
```

原因不是“逆矩阵永远错误”，而是：

- 显式构造完整逆做了不必要的工作；
- 产生更多舍入误差与存储；
- `solve` 能直接调用 LU、Cholesky 等适合结构的分解；
- 最小二乘、奇异或非方阵问题应使用 QR/SVD 路线，如 `lstsq`/`pinv`。

同样，判断矩阵“是否奇异”不能只看 `det(A) == 0`。行列式会随维数和尺度极端缩放，数值秩和奇异值更有解释力。

## 7. 概率计算为何常在 log 空间进行

许多小概率连乘会迅速下溢：

$$
p(x_{1:n})=\prod_{i=1}^n p(x_i).
$$

取对数后变成求和：

$$
\log p(x_{1:n})=\sum_i\log p(x_i),
$$

既更稳定，也更容易求导。归一化时使用

$$
\operatorname{LSE}(z)
=m+\log\sum_i e^{z_i-m},
\qquad m=\max_i z_i.
$$

交叉熵实现通常直接接收 logits，并把 `log_softmax` 与负对数似然融合，而不是先计算概率再取 `log`。后者可能把很小的概率先舍入成 0，再得到 `log(0)=-\infty`。

## 8. 混合精度训练的核心思路

低精度可以提升吞吐、减少显存，但不能机械地“所有张量全换成 FP16”。常见混合精度策略是：

- 大规模矩阵乘使用 BF16/FP16；
- 对累加、归一化、某些 reduction 和 master weights 保留更高精度；
- FP16 训练可能用 loss scaling，把过小梯度临时放大以避免下溢；
- 发现非有限梯度时跳过更新并调整 scale；
- 对极端 logits、方差和除法加稳定公式或合理的 epsilon。

epsilon 不是越大越稳定。它会改变所计算的函数；应说明它用于防止除零、平滑概率还是截断数值，并做敏感性检查。

## 9. 可运行示例：相同数学公式，不同数值命运

```python
import numpy as np

logits = np.array([1000.0, 1001.0, 1002.0])

# 直接 exp 会溢出；稳定版先减最大值。
with np.errstate(over="ignore", invalid="ignore"):
    naive = np.exp(logits) / np.exp(logits).sum()

shifted = logits - logits.max()
stable = np.exp(shifted) / np.exp(shifted).sum()

print("naive softmax:", naive)
print("stable softmax:", stable)

assert not np.all(np.isfinite(naive))
assert np.all(np.isfinite(stable))
assert np.allclose(stable.sum(), 1.0)

# 接近大数相减会丢掉小增量：float64 在 1e16 附近分辨不出 +1。
a = np.float64(1e16)
lost_increment = (a + 1.0) - a
print("(1e16 + 1) - 1e16 =", lost_increment)
assert lost_increment == 0.0

# 数学等价的稳定改写。
x = 1e-12
unstable = np.sqrt(1.0 + x) - 1.0
stable_rewrite = x / (np.sqrt(1.0 + x) + 1.0)
print("cancellation form:", unstable)
print("stable rewrite:", stable_rewrite)
assert abs(stable_rewrite - 0.5e-12) < abs(unstable - 0.5e-12)
```

## 常见误区

1. **“float64 就足够精确，可以当实数。”** 它仍是有限表示；病态问题和极端量级下照样失败。
2. **“结果有一点差异就是 bug。”** 并行归约顺序、硬件和库实现会造成末位差异；需要按任务设合理容差。
3. **“条件数大说明算法实现错误。”** 条件数描述问题敏感性；应再区分算法稳定性。
4. **“矩阵可逆，所以 `inv` 一定可靠。”** 理论可逆不等于数值良态，小奇异值会放大误差。
5. **“加一个 epsilon 就解决所有 NaN。”** 它可能掩盖上游错误或明显改变目标函数。
6. **“loss scaling 能防止所有混合精度问题。”** 它主要缓解梯度下溢，不能修复前向溢出、病态归一化或错误公式。
